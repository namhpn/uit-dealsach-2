# T0025 — ProductDetail Offer Cheapest Ordering Fix

## Goal

## Requirements

* Sort `offers.purchasable` in the public book-detail response by current eligible price ascending.
* Use the same price basis that makes an offer purchasable:

  * primary sort: `latest_price`
  * tie-breaker: offer id ascending
* Do not sort unavailable, stale-reference, or missing-link groups unless required by an existing failing test.
* Do not change the public API response shape.
* Do not change seeded prices or demo offer insertion order.
* Do not move cheapest-label logic into the frontend unless backend ordering alone cannot solve the proven mismatch.
* Add or update backend test coverage proving that a book with multiple purchasable offers returns `offers.purchasable[0]` as the lowest current eligible offer.
* Include the seeded example `Cho tôi xin một vé đi tuổi thơ` or a deterministic equivalent in test coverage.
* Confirm the summary `lowest_eligible_price` matches the first purchasable offer’s `latest_price`.
* Preserve existing eligibility exclusions:

  * stale observations are not purchasable,
  * unavailable latest observations are not purchasable,
  * invalid or missing seller links are not purchasable.
