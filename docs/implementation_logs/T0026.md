## Requirements

- Keep WishlistPage API-backed.
- Continue loading wishlist items through existing `fetchWishlist()`.
- Continue removing items through existing `removeWishlistBook(bookId)`.
- Preserve authenticated/guest behavior:
  - guests see a Vietnamese login prompt;
  - authenticated users see their saved books;
  - guest CTA opens the existing auth dialog.
- Preserve loading, error, empty, populated, and archived-book states.
- Preserve active book navigation to `/book/{bookId}`.
- Preserve archived book behavior:
  - archived saved books remain visible;
  - archived titles do not link to `/book/{id}`;
  - archived cards still allow `Bỏ lưu`.
- Do not introduce mock wishlist data.
- Do not copy the original page’s mock active/archived arrays.
- Do not reintroduce a full-width row-only layout.

### 1. Page header

- Replace the current plain heading/email header with a stronger original-reference header:
  - stamped `Danh sách yêu thích` title;
  - uppercase, extra-bold Be Vietnam Pro treatment;
  - black border;
  - hard 8px black shadow;
  - sharp corners;
  - optional slight `-1deg` rotation;
  - short explanatory text block with a strong emerald left rule;
  - saved-count badge showing `{items.length} cuốn đã lưu`.
- The logged-in email may remain visible, but it must not be the primary visual element.
- Header copy must remain Vietnamese.

### 2. Shelf structure

- Add a visible saved-books shelf header:
  - title: `Đang theo dõi`;
  - count pill beside the title;
  - hard black bottom divider.
- Keep archived books in the same grid by default.
- Do not add a separate archived shelf unless it is strictly conditional and does not weaken grid scan density.

### 3. Grid layout

- Keep the current production grid direction:
  - one column on small screens;
  - two columns on medium screens and above.
- Cards must have consistent visual rhythm and avoid excessive height variation.
- The page should feel like an e-commerce saved-products grid, not an account settings list.

### 4. Wishlist card shell

Each saved-book card must use a local WishlistPage card component with:

- white active background;
- `2px solid #000` border;
- hard black shadow;
- no border radius;
- horizontal layout with cover on the left and content/action area on the right;
- hover/focus treatment that feels tactile without breaking layout;
- no global `ApiBookCard` behavior changes.

### 5. Cover frame

- Use a fixed book-proportion cover frame.
- Keep cover left-aligned.
- Use a hard divider between cover and metadata.
- Use existing `CoverImage` fallback behavior.
- The cover frame must not stretch unpredictably because of long card content.

### 6. Metadata hierarchy

Each card must show:

- category as a bordered uppercase chip, not plain text;
- title:
  - active books link to `/book/{id}`;
  - archived books render as non-link text;
  - clamp long titles;
- author and publisher in a compact line;
- saved date from `added_at`, formatted for Vietnamese users where practical;
- no book description.

### 7. Price and status treatment

- If `lowest_eligible_price !== null`:
  - show a labelled current price block;
  - show `highest_eligible_price` as crossed reference price only when `highest_eligible_price > lowest_eligible_price`;
  - show `{offer_count} nơi bán` only when there is a current eligible price.
- If `lowest_eligible_price === null`:
  - show `book.status.label` as a strong rectangular status chip.
- Archived cards must show an `Đã lưu trữ` badge.
- Do not show `N/A`.
- Do not add a price-drop badge on WishlistPage in this ticket.
- Do not add discount percentages.
- Do not invent MSRP or unavailable reference prices.
- Do not add exact purchasable seller-count behavior unless an existing API field already supports it.

### 8. Price disclaimer

- Keep compact per-card reference-price disclaimer on WishlistPage.
- Constrain the disclaimer so it does not stretch card height or push the remove button awkwardly.
- Do not remove `PriceDisclaimer` globally.
- Do not change SearchPage bottom-disclaimer behavior.

### 9. Remove action

- Restyle `Bỏ lưu` as a tactile Neubrutalist button:
  - trash/remove icon;
  - uppercase text;
  - bone-white or white background;
  - 2px black border;
  - hard 4px shadow;
  - pressed state moves down-right and hides/reduces the shadow.
- Add per-item pending state while a remove request is in flight.
- Prevent duplicate remove clicks for the same card while pending.
- On remove failure, show a Vietnamese error and preserve or restore the item.
- Do not add a confirmation modal.
- Do not implement undo.

### 10. Guest, loading, error, and empty states

- Guest state must remain a bordered hard-shadow panel with login CTA.
- Empty state must include a clear Vietnamese message and a `/search` CTA such as `Khám phá sách`.
- Loading and error states must remain Vietnamese-first and visually consistent with the Neubrutalist system.
- Do not add skeleton loaders unless implemented locally without dependencies.

### 11. Backend fallback card compatibility fix

- In `WishlistService::listForUser()`, ensure the fallback card for archived/non-public books includes:
  - `highest_eligible_price => null`
- This is a compatibility fix only.
- Do not change wishlist persistence, add endpoints, add migrations, or alter public catalog semantics.
- Add or update focused backend coverage only if an existing wishlist test location is available or a small focused test can be added without broad refactoring.

### 12. Shared behavior preservation

- Do not regress Homepage card behavior.
- Do not regress SearchPage card behavior.
- Do not regress ProductDetailPage related-card behavior.
- Do not alter `ApiBookCard` defaults for this redesign.
- Prefer local WishlistPage components over shared component changes.
