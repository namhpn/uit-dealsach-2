### 2. Shared visual primitives

In `frontend/src/app/shared.tsx`, add small reusable frontend-only primitives for page styling. Keep them simple, dependency-free, and API-agnostic.

Add or refine these primitives without breaking current exports:

- `PageShell`
  - standard centered page wrapper;
  - supports variants:
    - `standard`: public/detail/user pages;
    - `wide`: search/dense pages;
    - `admin`: admin pages with contained horizontal overflow where needed;
  - uses DealSach background, Be Vietnam Pro, and consistent vertical spacing.
- `StampHeading`
  - reusable stamped title block;
  - supports optional icon;
  - supports `primaryFixed`, `white`, and `primary` visual modes;
  - always sharp-cornered, black-bordered, hard-shadowed.
- `PageIntro`
  - explanatory text with emerald left rule.
- `StatusChip`
  - small uppercase bordered chip;
  - supports primary, warning, muted, danger, success, and neutral variants.
- `SectionHeader`
  - title, optional count chip, optional description, and hard divider.
- `PromptCard`
  - reusable bordered card for unauthenticated, empty, blocked, and action-required states;
  - supports icon, title, description, CTA, optional secondary CTA.
- `NbIconButton`
  - square tactile icon button for header/admin/action use.
- `NbInput`
  - standard text input style for public/auth forms.
- `NbDenseInput`
  - compact input style for search filters/Admin tables.
- `NbSelect`
  - compact select wrapper or helper style, if practical without over-refactoring.
- `AdminHeader`
  - admin page title, description, optional icon, optional nav/actions.
- `AdminTableShell`
  - wrapper for dense admin tables with consistent background, border, shadow, overflow behavior.
- `AdminBackLink`
  - consistent `Về Admin` link styling.

Constraints:

- Do not change existing exported names in ways that break pages.
- Keep existing `C`, `FONT`, `border2`, `border3`, `border4`, `shadow4`, `shadow8`, `NbButton`, `LoadingState`, `EmptyState`, `ErrorState`, `CoverImage`, and book-card exports working.
- Do not change `ApiBookCard` default behavior except for purely internal style reuse that preserves rendered semantics.

### 3. Button standardization

Standardize page buttons around the DealSach tactile grammar.

- Primary buttons:
  - emerald background;
  - white text;
  - 2px black border;
  - 4px hard shadow;
  - pressed state translates down/right and removes shadow.
- Secondary buttons:
  - bone-white or white background;
  - black text;
  - 2px black border;
  - 4px hard shadow;
  - same pressed state.
- Danger buttons:
  - pale red or white background;
  - DealSach red text;
  - black border;
  - hard shadow unless intentionally compact.
- Text utility actions:
  - only for low-priority links such as `Về Admin`;
  - no hard shadow required.

Replace local hand-rolled buttons with `NbButton` or a new shared variant where practical.

Do not alter button labels or underlying API actions except where labels are purely visual and already user-facing.

### 4. Input/form standardization

Use two input families:

- Public/auth/user-facing inputs:
  - `NbInput`;
  - 3px black border;
  - white background;
  - bone-white/focus treatment where practical;
  - 13–15px text.
- Dense search/Admin inputs:
  - `NbDenseInput`;
  - 2px black border;
  - bone-white background;
  - 11–13px text.

Apply this to:

- auth dialog email/code inputs;
- ProductDetail alert target input;
- SearchPage price inputs and sort select where practical;
- AlertsPage inline target edit input;
- Admin create/edit forms and table inputs.

Do not change validation semantics.
