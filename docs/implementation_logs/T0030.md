## Requirements

### 1. Replace default 404 behavior

- Add a catch-all route under the existing root route:
  - `path: "*"`
  - render `NotFoundPage`
- The catch-all 404 page must render inside the normal `Root` shell so users still see:
  - sticky DealSach header
  - search input
  - category chips where loaded
  - account/wishlist/alert controls
  - footer
- The page must remove the current React Router default message:
  - `Unexpected Application Error!`
  - `404 Not Found`
  - `Hey developer`
  - `ErrorBoundary`
  - `errorElement`

### 2. Add branded route-error fallback

- Add `RouteErrorPage` for route-level unexpected errors.
- Use React Router error helpers where appropriate:
  - `useRouteError`
  - `isRouteErrorResponse`
- Do not expose stack traces, internal error object dumps, file paths, component names, or developer guidance in the visible UI.
- The visible UI must use Vietnamese-first user-facing copy.
- The fallback should distinguish common 404 route responses from unexpected errors when practical:
  - 404-style message: `Không tìm thấy trang`
  - unexpected-error message: `Có lỗi xảy ra`
- Keep diagnostics minimal and safe:
  - optional generic status chip such as `404` or `Lỗi hiển thị`
  - no raw stack/message details unless the message is already safe and user-facing.

### 3. Route configuration behavior

- Wire `NotFoundPage` as the final child route in `frontend/src/app/routes.tsx`.
- Wire `RouteErrorPage` as an `errorElement` or `ErrorBoundary` for route errors without breaking the existing `Root` shell.
- Prefer child-route-level error fallback where it preserves the parent shell.
- If adding a root-level fallback is necessary, it must still be DealSach-branded and must not display React Router’s default developer fallback.
- Do not change any existing route paths except adding the catch-all route and error fallback configuration.
- Do not remove or rename public, user, or Admin routes in this ticket.

### 4. 404 page styling

`NotFoundPage` must reuse the existing frontend visual language rather than creating a generic error screen.

Required layout:

- Use `PageShell`.
- Use a single centered hero/error card.
- Use `StampHeading` for the main title:
  - `Không tìm thấy trang`
- Use `PageIntro` or equivalent intro text:
  - `Đường dẫn này không tồn tại hoặc đã được thay đổi. Bạn có thể quay lại trang chủ hoặc tìm sách đang quan tâm.`
- Use existing `NbButton` for actions:
  - Primary CTA: `Về trang chủ`
  - Secondary CTA: `Tìm sách`
- Use one Lucide icon consistent with the frontend stack, such as:
  - `SearchX`
  - `Compass`
  - `Map`
  - `BookOpen`
- Use sharp Neubrutalist styling:
  - `C.white` card background
  - `border2`
  - `shadow8`
  - no rounded corners
  - dense but readable spacing
  - Be Vietnam Pro via shared tokens
- Use a small status chip or label for `404`, but do not overuse chips for every line of metadata.
- Optional helper copy:
  - `Bạn cũng có thể dùng ô tìm kiếm phía trên để tra cứu theo tên sách, tác giả hoặc ISBN.`
- The page must feel close to the current `WishlistPage`/user-page stamped style, not like a standalone browser error screen.

### 5. Route-error page styling

`RouteErrorPage` must use the same visual family as `NotFoundPage`.

Required layout:

- Use `PageShell` when rendered under the normal shell.
- Use a single centered card.
- Use `StampHeading` or `PromptCard`.
- Visible title:
  - `Có lỗi xảy ra`
- Visible description:
  - `DealSach không thể hiển thị nội dung này. Vui lòng thử lại hoặc quay về trang chủ.`
- Actions:
  - `Về trang chủ`
  - `Tìm sách`
- Use red only as controlled failure emphasis:
  - small chip, icon, or accent
  - do not make the whole page a red warning surface
- Do not show technical route error wording unless converted into safe Vietnamese copy.

### 6. DealSach product boundaries

- Keep copy aligned with DealSach’s scope:
  - DealSach compares reference book prices.
  - DealSach redirects users to external sellers.
  - DealSach does not sell books directly.
- Do not add checkout, cart, payment, shipping, order, review, rating, support-ticket, or marketplace-service language.
- Do not include the required price disclaimer on these error pages unless a price or Buy action is shown. This ticket must not add any price or Buy action to the 404/error pages.
