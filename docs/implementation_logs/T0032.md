# T0032 — Alert Auto-Evaluation, Email Retry, Footer Links, and Known-Issue Cleanup

## Goal

Make Admin-added price observations automatically evaluate alerts, harden alert email retry to at least 3 attempts, wire available footer links to real routes, and close completed known issues KI-0009/KI-0014.

## Dependencies

* T0031 completed or merged.
* Existing Admin catalog observation endpoint: `POST /api/admin/offers/{offerId}/observations`.
* Existing alert evaluator command: `alerts:evaluate`.
* Existing `AlertNotificationService`.
* Existing `AdminCatalogService`.
* Existing `Root.tsx` footer.
* Existing `docs/Known_Issues_And_Followups.md`.
* `.codex/skills/diagnostic-protocol/SKILL.md`.

Codex may edit only:

* `backend/app/Libraries/AdminCatalogService.php`

## Requirements

* Use `.codex/skills/diagnostic-protocol/SKILL.md` before changing code:

  * verify current price observation → alert evaluation → email flow;
  * trace where Admin observation insertion currently stops;
  * trace email retry behavior and identify the current retry limit.
* After `AdminCatalogService::addObservation()` successfully inserts a new `price_observation`, automatically run alert evaluation from application code.
* Do not implement this with a MariaDB SQL trigger.
* Keep alert evaluation logic inside `AlertNotificationService`.
* Preserve existing `price_observation_created` audit behavior.
* If practical without breaking callers, include an `alert_evaluation` summary in the Admin add-observation response.
* Alert email delivery must attempt at least 3 total sends before final failure.
* Existing mock failure behavior must remain testable.
* No duplicate alert email should be sent when the eligible price has not crossed the alert condition again.
* Alert evaluation must still ignore ineligible cases:

  * paused/disabled/expired alerts;
  * inactive users;
  * inactive/archived books;
  * stale offers;
  * unavailable offers;
  * invalid/missing seller links.
* Footer links currently rendered as `href="#"` must be replaced with working internal behavior where routes exist.
* Wire available footer links:

  * `Tìm kiếm sách` → `/search`
  * `Danh mục` → `/search`
  * `Danh sách yêu thích` → `/wishlist` for authenticated users; open existing auth dialog for guests.
  * `Cài đặt thông báo giá` → `/alerts` for authenticated users; open existing auth dialog for guests.
  * `Cài đặt tài khoản` → `/account` for authenticated users; open existing auth dialog for guests.
  * `Đăng nhập / Đăng ký` → open auth dialog for guests; route to `/account` if already authenticated.
* Footer items without implemented pages must not remain as broken active `href="#"` links.

  * They may be removed, rendered as disabled text, or routed only if there is a semantically accurate existing route.
* Preserve footer visual style.
* Move KI-0009 and KI-0014 from Open Items to Closed Items with closure date `2026-06-04`, based on reviewer confirmation.
* Keep KI-0016 open.
* Update repo state and manual verification docs.
