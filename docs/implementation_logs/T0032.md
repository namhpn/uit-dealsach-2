## Diagnostic Trace Findings

- Admin observation insertion happens in `AdminCatalogService::addObservation()`: it validates the payload, creates or reuses an observation cycle, inserts `price_observations`, and records `price_observation_created` audit data.
- Before T0032, the method returned `offerDetail($offerId)` after the transaction and did not call alert evaluation, so Admin observation insertion stopped before alert side effects.
- Alert evaluation is centralized in `AlertNotificationService::evaluate()`. The Spark command `alerts:evaluate` calls this same evaluator.
- Email retry behavior was in `AlertNotificationService::attemptEmailWithRetry()`, where the loop previously allowed only 2 attempts.
- Ineligible alert cases remain governed by `AlertNotificationService` and `PublicCatalogService::currentEligibleOffersForBook()`: inactive users, inactive/archived books, non-Active alerts, stale/unavailable offers, and invalid destinations do not produce eligible current offers or evaluable alerts.
